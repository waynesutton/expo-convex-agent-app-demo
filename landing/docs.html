what this is

expo-demo is a mobile agent chat app. You create bots, give each one a job, and message them like coworkers. Bots can share a group chat, answer @mentions, save skills you paste in, remember things between conversations, and send you reminders on a schedule.

It is two projects in one repo, which is what "monorepo" means:

FolderWhat it is
apps/nativeThe Expo app. React Native screens written in TypeScript, routed by file name with expo-router. This is what runs on your phone.
packages/backendThe Convex backend. The database schema, the agent loop, the tools, the cron jobs. This runs on Convex's cloud (or a local dev deployment).
landing/This site. Two static HTML files, no build step.
docs/The markdown docs this page is compiled from, with deeper detail per topic.

The two halves talk over one URL. The app holds a Convex client pointed at your deployment, and every screen reads data with reactive queries. When the backend writes a new message, the chat updates on its own. There is no polling and no websocket code in the app; Convex handles the transport.

Convex is a backend platform where your database, server functions, scheduled jobs, and file storage are all TypeScript. Expo is the toolchain that builds and runs the React Native app. Expo wrote about why the pairing works: Convex is a backend for Expo apps.

what you need

  • Node 20 or newer, npm 10 or newer. Check with node --version and npm --version. If you need an install, grab the LTS from nodejs.org.
  • Expo Go on your phone. Free app, App Store or Play Store. It runs the template during development so you skip Xcode and Android Studio entirely. A simulator works too if you have one.
  • A Convex account, or anonymous agent mode. Free tier, no card. The first npx convex dev walks you through login. Coding agents that cannot log in use CONVEX_AGENT_MODE=anonymous npx convex dev instead (no account).
  • No API keys required to browse the demo. A model key from Anthropic, OpenAI, xAI, OpenRouter, or Concentrate is only needed to send a live reply. You paste it into the app later, not into any file. Firecrawl, AgentMail, Merge, and Runware keys are optional.

That is the whole list. Git helps but even that is optional if you download the repo as a zip.

get your copy

Two ways to copy the repo, and the difference matters:

  • Use this template (the green button on GitHub) gives you a brand new repo with clean history. Pick this if you are building your own app on top.
  • Fork keeps a link to the original so you can pull upstream changes later. Pick this if you want future template updates.

Either way, clone your copy and install:

git clone <your-repo-url> expo-demo
cd expo-demo
npm install

npm install at the root installs dependencies for both the app and the backend, because the repo uses npm workspaces. You never run install inside the subfolders.

Shortcut for agent users. Open your copy in Claude Code, Cursor, or Codex and paste the setup prompt from the home page. The agent runs every step on this page for you. The rest of this guide is the manual path, and the map for when you want to know what the agent did.

set up the convex backend

The backend needs a deployment: a running Convex instance that holds your data and functions. One command creates it.

cd packages/backend
npx convex dev

First run does four things:

  1. Opens a browser for Convex login, or account creation if you are new.
  2. Creates a project and a development deployment inside it.
  3. Pushes the schema and functions from convex/, and generates the typed client in convex/_generated. The app imports its API types from there, which is why the folder is gitignored: every machine regenerates it.
  4. Prints your deployment URL, something like https://happy-otter-123.convex.cloud. Copy it, the app needs it next.

Leave this terminal running. It watches the backend files and pushes changes live while you develop. Closing it does not delete anything; your deployment keeps running in the cloud.

The Firecrawl component requires FIRECRAWL_API_KEY to exist before a push succeeds. You do not need a real key. Run this once from packages/backend:

npx convex env set FIRECRAWL_API_KEY unset

The app treats unset as not configured and keeps scrape/search out of the tool list until you replace it with a real fc-... key.

No login possible? Anonymous agent mode

Coding agents running unattended cannot click through a login page. Convex has a mode for that:

CONVEX_AGENT_MODE=anonymous npx convex dev

This downloads a local Convex binary, serves a full deployment at http://127.0.0.1:3210 with no account, and runs a local dashboard. Point the app at that URL instead. When a human takes over, run plain npx convex dev, log in, and swap the URL. Details at docs.convex.dev/cli/agent-mode.

Already on EAS? One command instead

If you use Expo Application Services, this replaces the manual provisioning and env writing:

npm install -g eas-cli
eas init
eas integrations:convex:connect

It creates the Convex project, writes EXPO_PUBLIC_CONVEX_URL to your local env file, and sets it across your EAS environments (development, preview, production) in one step. The dashboard invite arrives by email. This flow comes from the Expo guide to using Convex.

run the expo app

Open a second terminal (the backend keeps the first). The app reads its Convex URL from an env file you create once:

cd apps/native
cp .env.example .env.local
# open .env.local and paste the URL from the previous step:
# EXPO_PUBLIC_CONVEX_URL=https://<your-deployment>.convex.cloud
npx expo start

Expo prints a QR code. Scan it with your phone camera (iOS) or inside Expo Go (Android) and the app loads. First open seeds the posed demo: three bots with scripted chats and one group thread, so the screen is never empty.

.env.local is gitignored, so your URL never lands in a commit. The EXPO_PUBLIC_ prefix means the value ships inside the app bundle, which is fine here; the deployment URL is public by design. Never put a secret in an EXPO_PUBLIC_ variable.

No phone handy? Web preview

cd apps/native
npx expo install react-native-web react-dom
npx expo start --web

Same app in a browser tab. Two differences on web: key storage falls back to localStorage since the device keychain is native only, and push registration is skipped. Web is for previewing; the native app is the product.

add your model key

The template ships with no model key and proxies nothing through anyone's account. You bring your own. In the app, open Settings, pick a provider, paste the key.

ProviderKey prefixDefault model
Anthropicsk-ant-claude-sonnet-4-6
OpenAIsk-gpt-5
xAIxai-grok-4
OpenRoutersk-or-anthropic/claude-sonnet-4-6
Concentratevariesclaude-sonnet-4-6

Concentrate and OpenRouter are gateways: one key reaches every major model through an OpenAI compatible API. Pick one when you want to switch models without juggling provider keys. Default model IDs live in one map in packages/backend/convex/agent.ts if you want different ones.

Where the key goes, step by step: it is written to expo-secure-store (the iOS Keychain or Android Keystore), read back when you send a message, passed as an argument to the agent action over HTTPS, used for the one provider request, and gone when the action returns. There is no apiKey field in the schema on purpose, and the agent path never logs its arguments. Removing the key in Settings deletes it from the device immediately.

optional workspace tools

Four tools the bots can use. All optional: a tool with no key reports itself unavailable and the agent works around it. These keys belong to the app operator (you), not to users, so they live as Convex environment variables rather than on the device.

cd packages/backend
npx convex env set FIRECRAWL_API_KEY fc-...      # web scraping and search, firecrawl.dev
npx convex env set AGENTMAIL_API_KEY ...         # email for agents, agentmail.to
npx convex env set AGENTMAIL_INBOX_ID ...        # the inbox email address
npx convex env set MERGE_API_KEY ...             # business data, merge.dev
npx convex env set MERGE_ACCOUNT_TOKEN ...       # from Merge Link
npx convex env set RUNWARE_API_KEY ...           # image generation, runware.ai
ToolWhat bots can do with it
FirecrawlFetch any URL as clean markdown and run web searches that return page content. Also powers skill import from links. Uses the official @firecrawl/firecrawl-convex component: typed v2 API calls, retries on transient failures, and durable site crawls when your fork wants them. The component requires the env var to exist before a deploy, so with no key set it to the placeholder unset.
AgentMailSend email from the app's own inbox and list recent threads. Uses the official @agentmail/convex component: durable sends with retries and reactive delivery status. Register the webhook (see docs/integrations.md) and inbound mail lands in Convex tables too.
MergeRead HRIS, ATS, CRM, ticketing, and accounting data through one API. Ask a bot "how many open tickets do we have."
RunwareGenerate images on request and reply with the URL. Default model is FLUX.1 dev; swap the constant in convex/tools/runware.ts.

Every tool you enable works with all of your bots; the registry is shared. To add your own tool, copy the shape of convex/tools/merge.ts (a definition the model sees plus an execute function) and register it in convex/agent.ts. The chat UI renders any tool call generically, so no UI work. The Settings screen shows a Configured badge for Firecrawl and AgentMail without exposing any key.

how the app works

The agent loop

Everything runs through one readable Convex action, convex/agent.ts. When you send a message:

  1. A mutation writes your message to the database, then the app calls the runAgent action with the thread, provider, model, and your key.
  2. The action loads the thread history and creates an assistant message with status streaming.
  3. It calls the provider's chat API with the system prompt, history, and tool definitions.
  4. Text comes back in chunks; each chunk is appended through a mutation, and the chat updates instantly because the message query is reactive.
  5. Tool calls are recorded on the message (you see a tool card), executed, and fed back to the model. Up to 6 tool rounds per run.
  6. When the model stops, the status flips to done. If the app is backgrounded, a push notification fires.

The posed demo and the 5 minute reset

First open seeds three bots with scripted chats plus a group thread called Monday planning: a Chief of Staff, a Coach, and a Research Bot. A cron in convex/crons.ts rewrites the demo chats back to their script every 5 minutes, so the demo always opens clean. Type into a demo chat and watch it heal on the next sweep. Delete a demo bot and it stays deleted; the reset only touches demo bots that still exist.

The hosted demo also runs in demo mode: chats are public, messages are filtered for language, links, and spam, key entry is disabled in Settings, and visitor created content resets on the same cron. One env var (DEMO_MODE) turns all of it on; forks leave it unset and get a normal private install. The full guide is in docs/demo-mode.md.

Mentions and group chats

Type @ in the composer and an autocomplete strip lists your bots. A message that mentions bots goes only to those bots, in the order mentioned, and mentioning a bot not in the thread pulls it in. No mentions means every bot in the thread replies. The group icon on the home screen (visible once you have two bots) starts a group chat where bots read each other's replies and coordinate.

Skills and memory

Paste a link or a block of instructions into any chat and ask the bot to save it as a skill. The skill_import tool names it, stores it, and can assign it to the current bot or a teammate. URLs are read through Firecrawl when that key is set. Bots also carry memory: ask one to remember something and the remember tool appends it to a durable note that rides its system prompt. Both are visible and removable in bot settings.

Reminders

Each bot holds one reminder: a message, an interval from 30 minutes to daily, and a switch. A 5 minute cron sweeps due reminders and delivers each as a push notification that opens the bot's chat. Settings has a global toggle that silences everything without touching per bot schedules.

Search, avatars, and rename

The magnifying glass next to the settings gear searches bots, chat titles, and message text using Convex full text search: three search indexes in the schema, one query, results ranked and prefix matched as you type. Bot settings accepts a PNG under 2 MB as an avatar, stored in Convex file storage and validated server side. And once you fork, Settings has an app name field that rebrands the header without touching any demo content.

make it yours

The rename checklist for a fork that becomes a real app:

  1. App identity. In apps/native/app.json, change name, slug, and scheme, plus the bundle identifier under ios and the package name under android. Do this before your first EAS build.
  2. Package names. The three package.json files (root, app, backend) carry the template names.
  3. In app links. Set REPO_URL in apps/native/lib/links.ts so the About screen points at your repo, your README, and your docs.
  4. This landing site. Two constants at the top of the script in index.html: REPO_URL unhides the GitHub and Fork links, and DEMO_URL defaults to /app/, where the web demo lives once you host the site on Convex (next section). Point it elsewhere if you host the demo on another origin, or set it to "" to hide the demo links and the QR code. Both files in landing/ are static; Convex hosts them with one command, and GitHub Pages, Netlify, or Vercel work too.

Nothing in the template phones home. Once the URLs are yours and Convex is provisioned, the upstream repo has no runtime role. The full GitHub walkthrough, including how to mark your repo as a template, is in docs/github.md.

ship it

Development and production are separate Convex deployments. When you are ready:

cd packages/backend
npx convex deploy                                # pushes to production
npx convex env set FIRECRAWL_API_KEY fc-... --prod   # repeat for each tool key

Then build real binaries with EAS. Expo Go is for development only; push notifications and store submission need these:

cd apps/native
eas build --platform ios
eas build --platform android
eas submit --platform ios                        # lands in TestFlight first

Make sure the production EAS environment's EXPO_PUBLIC_CONVEX_URL points at the production Convex URL, not your dev one. Later, JS only changes can ship over the air with eas update. Two store notes: BYOK apps should say in the listing that users supply their own model key, and if you ever add third party sign in, Apple requires Sign in with Apple as an option. The full walkthrough is in docs/deploy.md.

host it on convex

The deployment that runs your backend can also serve this site and the web demo. The template wires it up with @convex-dev/static-hosting, a Convex component that stores built files in Convex storage and serves them over HTTP actions. No second host, no DNS, one URL:

PathWhat lives there
/ and /docs.htmlThis landing site, served from the landing/ folder.
/app/The Expo app exported for web, with SPA fallback so client routes survive a reload.
/api/...The backend's own HTTP routes, like the AgentMail webhook at /api/agentmail/webhook.

The component is already installed and configured in packages/backend/convex/convex.config.ts. From the repo root:

npm run site:preview   # upload both sites to your dev deployment, smoke test first
npm run site:deploy    # deploy the backend to prod, then upload both sites to prod

Preview lands at https://<dev-deployment>.convex.site, production at your prod deployment's .convex.site URL. The upload builds the Expo web export with the right Convex URL injected, so the demo always talks to the deployment that serves it. The full guide, including custom domains, is in docs/static-hosting.md.

First prod deploy? Env vars are per deployment, and the Firecrawl component needs FIRECRAWL_API_KEY to exist before a push succeeds. Run npx convex env set FIRECRAWL_API_KEY unset --prod from packages/backend once, or the deploy fails with a MissingEnvironmentVariable error.

when things break

SymptomLikely cause and fix
App loads but every screen is empty or spinningEXPO_PUBLIC_CONVEX_URL is missing or wrong in apps/native/.env.local. Fix the URL, then restart npx expo start; Expo reads env files at startup only.
TypeScript errors about _generatedThe typed client has not been generated yet. Run npx convex dev from packages/backend once; it creates convex/_generated.
Bot never repliesNo model key saved, or the key is invalid. Open Settings, re-paste the key. Then check the backend logs: npx convex logs from packages/backend shows the error from the provider.
Push notifications never arriveExpected in Expo Go on Android, and iOS needs a real device. Build a development build: eas build --profile development. See docs/push-notifications.md.
A tool says it is unavailableIts env var is not set on the deployment you are using. Set it with npx convex env set, and remember production needs --prod.
Demo chats look edited or messyWait up to 5 minutes. The reset cron rewrites them back to script on its next sweep.
Install or codegen fails on a fresh cloneVersions drift. Run npx expo install --fix, re-run npx convex dev, and update packages forward rather than pinning backward.

For anything else, npx convex logs is the first stop; the Convex dashboard shows the same logs plus your data, live.

the rules of this repo

  1. Convex Auth is the only auth path, and it is not wired yet. The app runs auth free, one device one workspace, and the seam for adding identity is documented in docs/auth.md. No Better Auth, no Clerk, no WorkOS.
  2. User model keys never touch the database or logs. Device keychain in, function argument through, gone after the request.
  3. The UI stays reactive. If you find yourself writing polling code, you took a wrong turn; use a query.
  4. Check the Convex components directory before hand building infrastructure. Push and email already come from components here; rate limiting, workflows, and RAG are a package away when your fork needs them.

That is the whole guide. Fork it, run it, break the demo chats, and watch them heal.
